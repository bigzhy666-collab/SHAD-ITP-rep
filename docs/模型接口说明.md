# SHAD 已训练模型接口

版本：模型集成接口 1.0 · 服务 0.5.0 · 2026-11-09

## 1. 接口定位

此接口已在 `backend/` 实现，运行在本机，只加载管理员登记的已训练模型。M0 的同步推理不保存任务、采样或结果；调用者收到结果后自行保存。前端异步检测业务已由 M2 实现并复用此适配层，详见 [检测任务接口](本地检测任务接口说明.md)；不能将同步返回和持久化历史混为一谈。

M1 已增加 SQLite、CSV 导入和六个可选温度测点透传，详见 [本地数据接口说明](本地数据接口说明.md)。同步推理仍不创建任务或保存结果，且不执行 CSV 导入的传感器体检门控。小时稀疏数据、短连续块和未经验证的拆批不能用于证明正常；限制见 [模型对照复核](模型对照复核.md) 及 [实施计划](本地后端实施计划.md)。

当前支持仓库的 `StationModel` pickle 格式，不代表任意 `.pkl`、ONNX、Torch 或原因分析模型均能直接加载。新增格式必须明确实现适配器并增加对照测试。没有训练、调参、在线学习或浏览器任意文件加载接口。

## 2. Windows 启动与验证

以下命令均在仓库根目录 PowerShell 中运行，首次安装依赖需要网络，安装后推理不联网。

```powershell
python -m venv .venv-backend
.\.venv-backend\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
.\.venv-backend\Scripts\python.exe -m backend
```

默认 `http://127.0.0.1:8765`，不自动加载示例或绑定国内站点。关闭服务使用 Ctrl+C。日志位于 `backend/data/logs/service.log`，运行目录和本地注册表不提交 Git。

`requirements-lock.txt` 是本轮验证使用的完整依赖版本，适用于 Windows/Python 3.12，含测试工具；`requirements.txt` 为运行依赖，`requirements-dev.txt` 为开发依赖声明。更新锁文件或替换模型依赖后需重新执行对照测试。

显式启用示例产物，用于接口对照（使用独立数据目录，避免混入自己的数据）：

```powershell
.\.venv-backend\Scripts\python.exe -m backend --registry backend/config/registry.example.json --data-dir backend/data/example-check
```

另一个终端生成并发送合成输入：

```powershell
.\.venv-backend\Scripts\python.exe -m backend.example_request --out backend/data/example-request.json
curl.exe --noproxy "*" -L --fail-with-body http://127.0.0.1:8765/api/runtime
curl.exe --noproxy "*" -L --fail-with-body -H "Content-Type: application/json" --data-binary "@backend/data/example-request.json" http://127.0.0.1:8765/api/model-inferences
```

此命令实际运行 `M1_s7.pkl`，但输入是合成数据；它证明推理接口可工作及与直接调用一致，不能证明模型现场效果。示例原历史时区未确认，注册表的 `Etc/UTC` 仅为合成对照测试约定；不是对原站时区的判断。该示例组织 ID 与前端国内组织隔离，不能直接当作国内站点部署。

开发前端代理时：

```powershell
.\.venv-backend\Scripts\python.exe -m backend --dev-origin http://127.0.0.1:5173
```

`--dev-origin` 可重复，但只接受明确的本机 HTTP 地址，不支持通配。前端能连接此服务并查看能力状态；M1/M2 已开启导入、采样查看和后台检测；模型/数据/范围符合条件时业务检测按钮可用。原因和归档仍禁用。

提供已构建的前端：

```powershell
npm run build
.\.venv-backend\Scripts\python.exe -m backend --serve-frontend
```

同源提供页面与本机 API，不需要开发代理。安装器与包含 Python 的便携包仍为后续阶段。

## 3. 模型登记

复制 `backend/config/registry.example.json` 为被忽略的 `registry.local.json`，由管理员改为本站资料并启动时指定。仅修改 JSON 不会自动热加载，需重启服务。站点包含企业、管网、管段的稳定 ID 和时区；必须先用组织接口登记该路径，或在可信注册表 organizations 中按 enterprises/networks/segments 写入对应行。登记结果持久化到所选数据目录，重启不传 --registry 也保留登记；停止使用某目录时不会自动删除模型登记。已登记版本、站点或时区不能原地覆盖。

模型登记字段：

| 字段 | 含义 |
|---|---|
| `id/version` | 不可变版本标识；同一对值禁止重复 |
| `stationId` | 已登记的适用站点，不能擅自跨站 |
| `artifact` | 相对 `ml/models/` 的 `.pkl` 文件名/子路径；目录外路径和符号链接逃逸被拒绝 |
| `artifactChecksum` | 实际文件 SHA-256 小写 64 位 |
| `trainingTimezone` | 模型实际采用的 IANA 时区，必须与站点匹配 |
| `isDemo` | 是否示例/测试模型，真实部署必须如实填写 |
| `name/description` | 显示名称及适用说明 |

`Get-FileHash -Algorithm SHA256 ml/models/文件名.pkl` 可核查校验值。服务在反序列化之前校验目录与摘要，每次推理重新核对文件；同版本文件变化会变为不可用。pickle 本身具有执行代码能力，因此只有受信任的模型交付可进入受管理目录；hash 不能证明来源可信。

当前依赖固定为 Python 3.12、scikit-learn 1.9.1；遇到 pickle 版本不一致提示，服务标记模型不可用，不静默忽略警告。注册查询保留不可用项的登记信息及 `status=unavailable`，此时实际算法参数可能无法读取，不能选择执行。

## 4. HTTP 公共规则

- 只监听 `127.0.0.1`，无云端地址；Host 只接受本机，写操作校验 Origin，无通配 CORS。
- 成功：`{"requestId":"...","data":...}`；失败：`{"requestId":"...","error":{"code":"...","message":"...","retryable":false,"details":[]}}`。
- 返回真实数值，不允许 JSON NaN/Infinity；未知值用 null。错误响应不回传输入内容、Python 堆栈或本机绝对路径。
- 分页 `page>=1`、`1<=pageSize<=500`，默认每页 20；data 为 `{items,page,pageSize,total}`。
- OpenAPI 位于 `GET /api/openapi.json`，该路径返回标准 OpenAPI 文档而非 data 包装；离线可获取，无 Swagger 在线脚本依赖。

## 5. 模型及站点查询

`GET /api/stations?segmentId=seg-example&page=1&pageSize=20` 查询注册站点。

`GET /api/models?stationId=station-example-m1-7&page=1&pageSize=20` 返回版本、站点、校验值、时区、scoreKind、featureMode、cyclic、adaptive、cThr、quantile、八核心输入、optionalFields 六可选输入及实际 trainingFeatureColumns。`trainedAt` 未知时为 null，不编造训练日期。

查询会尝试加载可信模型并核验环境；不可用时 status=unavailable，接口不返回受管理文件的绝对路径。

## 6. 执行推理

`POST /api/model-inferences`，Content-Type 为 application/json，成功返回 200。此为同步接口，最多 5000 个采样且请求体不能超过 5 MiB；超出应缩小检测区间；不能独立拆批后拼接并声称等价，后续状态化方案需另行验证。不提供计时器假进度；单执行器忙时返回可重试的 `MODEL_BUSY`。

### 6.1 输入

```json
{
  "stationId": "station-example-m1-7",
  "modelId": "station-nbm-m1-7",
  "modelVersion": "example-1",
  "timezone": "Etc/UTC",
  "units": {
    "outdoor_temperature": "degC",
    "p_net_supply_temperature": "degC",
    "p_net_return_temperature": "degC",
    "p_net_meter_heat_power": "kW",
    "p_net_meter_flow": "L/h",
    "p_hc1_return_temperature": "degC",
    "s_hc1_supply_temperature": "degC",
    "s_hc1_supply_temperature_setpoint": "degC"
  },
  "samples": [{
    "timestamp": "2017-11-18T00:00:00+00:00",
    "values": {
      "outdoor_temperature": 5,
      "p_net_supply_temperature": 80,
      "p_net_return_temperature": 45,
      "p_net_meter_heat_power": 100,
      "p_net_meter_flow": 2500,
      "p_hc1_return_temperature": 35,
      "s_hc1_supply_temperature": 55,
      "s_hc1_supply_temperature_setpoint": 55
    }
  }]
}
```

以上单点请求可运行但会提示上下文不足；完整合成输入由命令生成。

输入要求：

1. stationId、modelId、modelVersion 必须登记；模型站点与输入站点相同，timezone 与站点/模型登记值一致。
2. units 必须包含全部八核心字段；可以加入已支持的六个可选温度字段（清单见数据接口说明），单位为 degC。功率/流量使用表中的标准单位，不在此接口隐式转换。CSV 的单位换算、排序及重采样已经在 M1 导入阶段实现。
3. 每个 values 的键必须恰好与 units 一致，八核心必需、可选字段按声明传入；允许 null，禁止数值字符串、布尔、无穷及白名单以外的字段。已提供的可选测点必须透传，不能为凑八字段丢弃。
4. 温度范围 [-60,220] degC，功率/流量非负；越界阻断。任一连续块的任一核心字段超过 80% 缺失，阻断检测；其余缺失由已有模型的训练期补值处理。
5. 时间必须为带偏移的 ISO8601，转为站点时间后对齐半小时；严格递增、不重复。不自动排序，也不添加历史上下文。
6. 按站点墙上时间给模型构造索引；物理时间或墙上时间不连续均分块，不跨缺口延续 criticality。包含夏令时回拨的重复墙上时间需拆分，不能静默合并。
7. 禁止额外提交模型路径、threshold、cThr、模型训练配置等覆盖参数。

### 6.2 输出

data 的结构：

| 字段 | 内容 |
|---|---|
| `stationId/modelSnapshot` | 本次使用的明确站点与真实模型参数/版本/校验值 |
| `preprocessingVersion` | 当前适配器为 `normalized-30min-blocks-v2`；CSV 导入独立记录 `csv-utf8-units-30min-quality-v1` |
| `range` | 输入首末点，站点时区 ISO8601 |
| `summary` | pointCount、alarmPointCount、confirmedPointCount、eventCount、blockCount、qualityIssueCount（本接口为缺失值数量） |
| `warnings` | 真实的示例模型、缺口或不足 24 小时上下文提示 |
| `points` | timestamp、blockId、score、threshold、alarm、criticality、health、confirmed |
| `segments` | 每段确认异常的 blockId、start/end、hours、peak_score、max_criticality、边界及空原因字段 |
| `persisted` | 恒为 false，不产生历史任务/报告 |

输出规则严格保留模型含义：

- alarm 为 score > threshold。
- criticality 在一个连续块中从 0 开始，alarm 时加 1，否则减 1 且不低于 0。
- confirmed 为 criticality >= 模型 cThr；alarm=false 仍可能 confirmed=true。
- health 为原模型公式 `clip(1-score/threshold,0,1)`，不是准确率或原因概率。
- 确认区间按 confirmed 连续点合并，不跨块；end 为最后确认点，hours 为首末时间差，单点为 0。
- boundary 相对本次输入首末点，不能将区间边缘误称为异常真实开始/结束。
- segments 不带业务 detectionId 或稳定事件 ID；M2 保存结果后分配稳定事件 ID。前端不能把这些临时区间当作已归档事件。
- 无异常为成功且 segments=[]，不是失败；不存在来源明确的具体原因时 cause/solution/affectedMetrics 为 null。

### 6.3 错误

| HTTP | code | 处理 |
|---|---|---|
| 400/422 | INVALID_REQUEST | 修正 JSON、字段类型、数量或多余参数 |
| 403 | LOCAL_ACCESS_REQUIRED / ORIGIN_REJECTED | 使用本机同源调用或明确的开发 Origin |
| 404 | NOT_FOUND | 检查模型登记 ID 和版本或接口路径 |
| 413 | REQUEST_TOO_LARGE | 请求超过 5 MiB，缩小范围；未经验证不独立拆批 |
| 422 | STATION_BINDING_REQUIRED / SOURCE_MISMATCH | 检查站点登记与模型适用关系 |
| 422 | TIMEZONE_MISMATCH / TIME_RANGE_INVALID | 核查时区、半小时对齐、顺序及夏令时区间 |
| 422 | UNIT_UNSUPPORTED / REQUIRED_FIELD_MISSING / DATA_QUALITY_BLOCKED | 修正标准化输入 |
| 503 | MODEL_UNAVAILABLE | 核查可信文件、校验值和依赖版本；查日志 |
| 503 | MODEL_BUSY | 当前执行完成后再提交，无后台排队 |
| 500 | MODEL_EXECUTION_FAILED / MODEL_OUTPUT_INVALID | 不返回虚构结果，按 requestId 查日志 |
| 503 | CAPABILITY_UNAVAILABLE | 对应业务阶段尚未实现 |

## 7. 内部复用入口

```python
from pathlib import Path
from backend.registry import ModelRegistry
from backend.model_adapter import ModelService
from backend.schemas import InferenceInput

registry = ModelRegistry(Path("backend/config/registry.local.json"))
service = ModelService(registry)
result = service.infer(InferenceInput.model_validate(payload))
```

内部入口与 HTTP 使用同一校验和推理逻辑。M2 后台任务在校验/标准化数据后直接调用此层，不需要再通过 HTTP 递归调用自己，也不能调用模型 fit/train。需要增加大批量模式时在执行器和适配器明确分块/上下文语义，不盲目切片而改变结果。
