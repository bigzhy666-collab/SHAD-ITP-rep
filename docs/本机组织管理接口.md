# 本机企业、管网与管段管理

2026-11-10；服务 0.6.0；契约 1.0；数据库 schema 4。

## 使用流程

本机模式进入管网管理，在「组织维护」选择企业、供热管网或管段，填写名称及编码创建；管网需先选择企业，管段需先选择管网。表内编辑可以修改名称、编码、启用状态。编码只允许字母、数字、点、下划线和短横线，同一上级内不区分大小写判重。修改成功后三级选择和顶栏同步，所选管段单独保存于本机模式的浏览器偏好；组织记录由后端保存，切换演示模式不会覆盖两侧组织。

停用企业或管网会使下属路径不可用，但不批量改写下属启用标记；重新启用上级后可恢复选择。停用后阻止新增下级、绑定站点及创建新检测；已保存检测和报告仍按来源快照读取，已创建任务可按原规则继续执行。不提供物理删除、跨上级移动或换站功能。

组织缺失时不自动使用演示组织补齐。读取失败显示错误和重试入口。新对象的管径、长度和测点不从演示数据套用，尚未登记的管径不会在顶栏显示。单位及实际检测输入仍由站点和数据集决定。

## 接口

- `GET /api/organizations`：返回 enterprises、networks、segments 数组。每行包含 id、name、code、active（布尔）、revision（初始 1）；管网含 enterpriseId，管段含 networkId。
- `POST /api/enterprises`：name、code；新企业。
- `POST /api/networks`：name、code、enterpriseId；新管网。
- `POST /api/segments`：name、code、networkId；新管段。
- `PATCH /api/organizations/{kind}/{id}`：kind 限 enterprises/networks/segments；body 为 name、code、active、expectedRevision。成功 revision 加一。不能传入或改写上级 ID。
- `GET /api/runtime`：新增 capabilities.organizationManagement=true。

冲突返回 409：ORGANIZATION_CONFLICT 为编码重复/无效上级，ORGANIZATION_INACTIVE 为停用路径，REVISION_CONFLICT 为修订已改变。修订冲突不会覆盖数据，页面保留当前输入，刷新组织、重新编辑并核对后保存；无强制覆盖入口。名称为空/字段非法返回 422，不存在对象返回 404。沿用本机来源限制与请求编号。

## 数据升级、重启与备份

schema 4 在原三张组织表增加 active 和 revision，旧记录默认启用、修订 1，ID 和关系不变。重新启动不会重置本地改名或停用状态；管理员注册表只补充缺失组织并校验既有上级关系，不再以旧名称覆盖本机维护。站点与同版本模型登记仍受原有不可覆盖约束。

离线备份/恢复支持 schema 3 和 4，4 包含停用状态和修订值；恢复旧 schema 3 后首次启动升级到 4。程序版本更旧时拒绝打开 schema 4，回退程序前应使用对应旧备份恢复到新目录。备份仍不包含模型文件、控制凭据或浏览器偏好。
