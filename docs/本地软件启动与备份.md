# SHAD 本地启动、停止与数据备份

版本：M5 第一批 · 服务 0.6.0 · 数据库 schema 4 · 2026-11-09

本批提供开发工作区可用的启动/停止入口和经过校验的备份恢复工具。仍需要现有 Python 3.12 环境和已构建的前端；无需 Python/Node 的 Windows 安装包及新电脑离线验收属于后续交付；组织维护同步已完成，不把这些脚本称为安装包。

## 一、日常打开和停止

首次准备沿用 README 的环境安装，在项目根目录运行 `npm run build`。已安装依赖、已有 `.venv-backend` 和 `dist` 时，可直接：

- 双击根目录的 `启动SHAD.cmd`：后台启动本机服务并打开浏览器，直接进入“本机服务”模式。页面通过 `127.0.0.1` 访问电脑内的服务，不连接云端。
- 再次双击启动：若同一数据目录已有受管理实例，打开原实例，不重复启动后台任务。
- 双击 `查看SHAD状态.cmd`：显示对应数据目录是否存在已识别的受管理服务，以及数据位置。手动启动的服务需要在原窗口核查。
- 双击 `停止SHAD.cmd`：验证当前实例和专用凭据后请求退出。关闭浏览器窗口仅关闭界面，不等于停止后台服务。
- 服务停止后双击 `备份SHAD.cmd`：生成带时间的新备份文件，屏幕显示保存位置。软件运行中会阻止离线备份，不会假报成功。

停止只针对此数据目录记录的 SHAD 实例，不按进程名称或 PID 强杀。正在执行的检测在退出时停止；完成结果不丢失，未完成任务按既有恢复规则保留或标记中断，可重试。排队任务在下次启动继续执行。等待退出超时时，先查询状态，不强制结束其他进程。

## 二、数据目录与旧数据

**启动脚本默认目录为 `%LOCALAPPDATA%\SHAD\data`**，也可通过 `SHAD_DATA_DIR` 或 `--data-dir` 指定。数据库、原 CSV、日志和启动记录都放在该目录，避免以后更新程序时覆盖业务记录。

此前直接运行 `python -m backend` 的开发默认目录仍是项目下 `backend/data`。这两个入口的默认目录不同；首次双击启动可能看到一个新工作区，旧数据没有被删除，也不会被自动搬迁。

要继续使用原项目数据，在项目根目录的 PowerShell 运行：

```powershell
.\启动SHAD.cmd --data-dir backend/data
.\查看SHAD状态.cmd --data-dir backend/data
.\停止SHAD.cmd --data-dir backend/data
.\备份SHAD.cmd --data-dir backend/data
```

所有操作应使用同一个数据目录。更换目录是在切换独立工作区，不是把已有记录复制过去。需要迁移时使用下面的备份恢复流程。

端口默认 8765。被其他程序占用时不会关闭该程序或改写其数据，检查 `logs/launcher.log` 后可指定：

```powershell
.\启动SHAD.cmd --data-dir backend/data --port 8766
```

日志：`logs/service.log` 按大小轮转；`logs/launcher.log` 保存启动失败等输出。启动记录 `desktop-runtime.json` 保存实例标识和私有停止凭据，不提交、不打包、不备份，不在 HTTP 状态中返回凭据。异常退出留下的有效旧记录会在下一次启动时与实际实例核对；格式损坏时应先确认服务已停止，再由维护人员移走该记录。不要删除正在使用的锁文件。

## 三、管理员命令

以下命令与快捷入口调用同一实现。默认输出 JSON 便于验收，添加 `--human` 输出中文状态。

```powershell
.\.venv-backend\Scripts\python.exe -m backend.desktop start --data-dir backend/data
.\.venv-backend\Scripts\python.exe -m backend.desktop status --data-dir backend/data
.\.venv-backend\Scripts\python.exe -m backend.desktop stop --data-dir backend/data
```

start 支持 `--port`、`--registry`、`--model-dir`、`--no-browser`。默认不登记或套用示例模型。registry 仍是管理员维护的本站模型登记，model-dir 是可信已训练产物目录；默认 `ml/models`。更换可信模型目录时，启动、备份和恢复应使用同一目录。

启动管理器在后台启动服务，服务只监听本机；正式入口先预留端口、取得数据目录锁，再初始化数据库、登记模型和启动队列。端口冲突或维护占锁时不会先迁移另一个数据库。

## 四、备份内容与校验

先停止对应服务。默认备份位置是数据目录旁的 `backups` 文件夹，文件名含 UTC 时间；也可指定新文件：

```powershell
.\.venv-backend\Scripts\python.exe -m backend.maintenance backup --data-dir backend/data
.\.venv-backend\Scripts\python.exe -m backend.maintenance backup --data-dir backend/data --output backend/backups/SHAD-20261109.shad-backup.zip
```

备份文件必须位于原数据目录之外，且不能覆盖旧文件。文件完成后才发布到目标位置，失败会清理本次临时文件，不提示已完成。

备份包含：

| 内容 | 范围 |
|---|---|
| `shad.sqlite3` | 组织、站点、模型登记、数据集与标准化采样、检测配置/状态、逐点/事件、报告快照/备注/归档/版本、去重记录 |
| `sources/*.csv` | 仅数据库实际引用的原始文件，与导入时 sourceChecksum 一致 |
| `manifest.json` | 备份格式版本、服务/数据库版本、创建时间、每个文件的大小与 SHA-256、模型登记清单 |

采用 SQLite backup 机制取得完整快照，包含 WAL 中已提交的数据；不会只复制主数据库而遗漏 WAL。备份前检查数据库完整性、外键、源文件和当前可信模型校验值。

**备份不包含模型 pickle、程序代码、环境、日志、控制凭据或浏览器演示记录。** 模型文件由管理员从原受信交付包另行保管和安装，恢复时核验已有模型与登记校验值，不从 ZIP 导入或执行模型代码。当前支持 schema 3/4 的数据库；旧开发数据先用当前服务完成升级再备份。

当前上限：展开后 4 GiB、单文件 2 GiB、最多 100001 个数据文件、清单 16 MiB。超过限制会拒绝，不能静默跳过部分数据。

## 五、恢复到新目录

只恢复自己或可信维护人员提供的备份；清单中的 SHA-256 用于检验完整性，不是发布者数字签名。

1. 停止当前服务，并记下原数据目录。
2. 准备一个**尚不存在**的新目录。已有目录即使为空也不覆盖，原数据库保持不变。
3. 检查所需模型已安装在可信模型目录，再执行恢复：

```powershell
.\.venv-backend\Scripts\python.exe -m backend.maintenance restore --archive backend/backups/SHAD-20261109.shad-backup.zip --data-dir backend/data-restored
```

4. 工具在同一目标父目录内暂存并校验所有文件：文件清单/大小/SHA-256、数据库完整性和外键、实际引用的源文件、模型登记与可信产物。拒绝越界路径、重复条目、链接、未知文件、超大或高版本包。不会使用 `extractall` 直接展开任意路径。
5. 全部通过后发布新目录，再从恢复目录启动：

```powershell
.\启动SHAD.cmd --data-dir backend/data-restored
```

6. 核对站点、数据集、检测点数、所选事件、报告备注、归档和版本；继续使用恢复目录。若有问题，停止该实例，再指定原目录启动即可；不要同时在同一端口启动两个目录。

恢复失败不会留下可误用的半成品工作区，也不改写原目录。当前数据库中的 queued/running 状态保留在备份中，恢复后的首次启动执行既有队列恢复规则，不把未完成任务改成成功。

## 六、接口与边界

`GET /api/runtime` 新增 desktop：手动服务为 `{managed:false}`；受管理服务为 `{managed:true,instanceId,pid}`。`POST /api/desktop/stop` 接受空 JSON 对象和私有 `X-SHAD-Control` 请求头。未托管返回 409，凭据错误/跨站请求返回 403；不匹配的实例不会收到管理器停止请求。此接口不改变模型/报告业务能力。

实际验收见 [M5 第一批记录](../verification/backend-m5-startup/验收记录.md)。后续还需：无需开发环境的 Windows 安装包、升级/卸载保留数据、干净电脑离线验收，以及本站真实模型验证。具体原因及方案诊断已取消。
