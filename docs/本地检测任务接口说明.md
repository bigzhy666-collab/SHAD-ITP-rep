# SHAD 本地后台检测接口与操作说明

版本：M2 检测接口（M3 更新）· 服务 0.5.0 · 数据库 schema 3 · 2026-11-09

## 当前可以完成的流程

本站 CSV → 本地数据集 → 选择本站模型与范围 → 持久化任务 → 单队列运行真实模型 → 保存逐点结果与确认事件 → 页面定位/勾选 → 临时证据报告和 Word/PDF。

`dataImport/anomalyDetection/offlineDetection` 已开启；执行器未启动或已停止时，检测能力返回 false。`reportPersistence=true`、`causeDiagnosis=false`。当前模型判断综合运行状态偏离，不返回具体故障原因或解决方案；备注及报告归档已在 M3 实现，具体原因仍等待独立模型。检测记录已经持久化，与报告存档是不同能力。

## 如何在本机使用

仓库根目录 PowerShell：

```powershell
.\.venv-backend\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
npm run build
.\.venv-backend\Scripts\python.exe -m backend --serve-frontend
```

打开 `http://127.0.0.1:8765/networks`，右上角选择“本机服务”。按 [数据接口说明](本地数据接口说明.md) 登记换热站和上传 CSV；管理员按 [模型登记说明](模型接口说明.md) 显式登记本站训练产物。进入数据集的“查看采样与检测”，确认站点、数据集、模型及起止时间后创建检测。

默认不自动加载仓库历史示例，也不会把它套到新建国内站。没有本站适用模型时，检测按钮继续禁用。模型的时区、物理侧别、采样要求及实际适用站点须由交付资料确定。检测参数从训练产物读取，不能由前端覆盖。

真实检测完成后可查看分数/阈值、定位和勾选事件；进入 AI诊断页可核查实际证据、保存备注、归档、创建新版本并导出 Word/PDF。具体原因能力仍禁用；报告已保存到本机 SQLite，见 [报告接口](本地报告接口说明.md)。

关闭网页不取消任务；退出后端后不承诺继续计算。再次启动同一数据目录会恢复历史，按下述规则处理未完成任务。

## 请求与接口

公共成功/失败封装、分页、Host/Origin 约束沿用 [本机接口约定](本机接口约定.md)。任务 ID、模型和数据都由本地服务校验，不接收文件路径、前端阈值、演示 scenario、假进度或训练参数。

| 方法与路径 | 参数 | 成功响应 |
|---|---|---|
| POST `/api/detections` | 下方 JSON；必须有 Idempotency-Key | 202，已保存的任务 |
| GET `/api/detections` | stationId、segmentId、status、page、pageSize 可选 | 200，历史分页 |
| GET `/api/detections/{id}` | 无 | 200，任务与当前阶段；失败任务也返回 200 |
| GET `/api/detections/{id}/result` | 无 | 200，固定来源、摘要、warnings、links |
| GET `/api/detections/{id}/points` | start、end、page、pageSize 可选 | 200，真实逐点结果分页 |
| GET `/api/detections/{id}/events` | start、end、page、pageSize 可选 | 200，确认告警事件分页 |
| POST `/api/detections/{id}/retry` | 空 JSON `{}`；必须有新的 Idempotency-Key | 202，新任务，retryOf 指向旧任务 |

```json
{
  "name":"本站历史运行检测",
  "context":{
    "enterpriseId":"实际企业ID",
    "networkId":"实际管网ID",
    "segmentId":"实际管段ID",
    "stationId":"实际换热站ID"
  },
  "datasetId":"实际数据集ID",
  "modelId":"管理员登记模型ID",
  "modelVersion":"实际登记版本",
  "range":{
    "start":"2026-11-08T00:00:00+08:00",
    "end":"2026-11-09T00:00:00+08:00"
  }
}
```

Idempotency-Key 长度 1–128，仅接受字母、数字、点、下划线、冒号和连字符。前端使用已有提交编号；同一路径/操作、同键及同内容重复请求返回原任务（可能已运行/完成），不会再计算；同键异内容返回 409。比较使用解析后请求对象的规范 JSON 摘要，不受 JSON 键顺序影响。记录与任务同事务保存，重启后继续有效。

首次创建先验证，验证失败不创建历史；只有 202 表示任务已被保存。请求超时应使用原提交编号再次查询/提交，不能立即换新编号。用户明确再次检测才使用新键。重试创建新 ID，保持原来源快照、范围和配置，不修改旧失败记录；同一重试编号的重复调用仍返回同一新任务。

## 创建和执行前的校验

- 企业→管网→管段→站点、数据集所属和模型适用站点完全一致；数据集 ready；模型版本已登记且校验值/依赖可用；站点、数据和模型时区一致。
- 范围为带时区的完整 ISO8601，开始早于结束，且在数据集范围内；范围内至少一个实际点，最多 5000 点。小时稀疏或选定区间的间隔中位数超过半小时会阻断，不偷偷补点或独立拆批。
- 使用全部已提供的核心/可选测点及标准单位；不是页面只显示哪个参数就只提交哪个测点。
- 范围整体或任一连续块内，核心测点 invalid/missing 质量标记超过 80% 则阻断；核心 null 缺失也单独检查。半小时 bin 即使有有效均值，仍不能用它掩盖大量无效原始值。
- 所选连续块至少 72 小时时再次运行传感器质量核查；严重室外测点问题阻断，其他发现提示。不会删除训练特征、改阈值或假装自动降级。
- 短块按实际 cThr 返回持续性上下文不足提示；无确认事件不代表状态正常。模型可处理的短块仍可成功，不能误报任务失败。

创建时冻结对象、数据集版本/校验值、模型版本/校验值/真实算法参数和范围；执行时再次验证，检测到来源变化则失败，不使用新来源覆盖原任务。

## 状态、保存和恢复

```text
queued → running(validating → detecting → saving) → success(completed)
                                                └→ failed
failed 且 error.retryable=true → 创建新任务 queued
```

`progress` 恒为 null，没有模型回调时只显示实际阶段。任务持有 createdAt/startedAt/finishedAt；没有发生的时间和 error 为 null。单个后台线程按创建时间及 ID 顺序领取任务；检测和同步模型验证共用模型锁，模型忙时后台任务等待，不直接标失败。

数据库 schema 2 新增 detections、idempotency_keys、detection_results、detection_points、detection_events。结果摘要、全部点、稳定事件 ID 和 success 在同一事务提交；中间失败全部回滚，不出现 success 却缺少结果的正常状态。失败记录保留可读错误；如果磁盘连失败状态都无法写入，保留原状态并记录日志，下次启动按中断恢复，不假装成功。

启动前持有数据目录的操作系统独占锁 `service.lock`；同一目录不允许两个服务同时运行/恢复任务。锁文件保留在磁盘，是否锁定由操作系统决定，不能通过手动删除锁文件强开第二个服务。进程退出或崩溃后锁会释放。

- 完成的 success/failed 及结果保持不变。
- queued 在下次启动后继续执行。
- 遗留 running 改为 failed，错误 TASK_INTERRUPTED，可明确创建重试。
- 正常关闭会停止领取新任务，等待执行线程最多 10 秒；无法中断的模型计算不承诺继续完成。进程退出前未提交的事务不会发布成功。

schema 1 数据会自动升级到 2，保留原组织/站点/数据；旧版服务拒绝打开高版本数据库。升级前可停止服务并备份完整数据目录；回滚软件版本时需要匹配的数据备份，不能只切换代码后直接降级打开新库。安装器及自动备份恢复继续 M5。

## 结果和查询语义

`result` 固定 contextSnapshot/datasetSnapshot/modelSnapshot/range，另含 computedAt、preprocessingVersion、summary、warnings、links。`sampleRange` 为实际选中点的首末时间，与用户请求范围区分；不擅自添加范围外历史进行预热。数据导入预处理版本和模型适配预处理版本分别保留。

逐点输出保留 timestamp、blockId、score、threshold、alarm、criticality、health、confirmed；缺口分块，每块从 criticality=0 开始。不能把逐页查询结果再次送入模型，也不承诺跨任务累计。健康度不是故障概率，综合分数不是某一个温度/压力的直接超限。

事件按 confirmed 的连续区间生成，ID 一次保存后固定。单点事件 hours=0，end 为最后一个确认点，不自动加半小时。当前 cause/solution/affectedMetrics 均为空，不编造具体原因。boundary 相对用户请求范围；触及结束不代表已恢复。没有事件仍是成功，仍可查看点级 alarm 曲线及上下文提示。

points 按时间升序并按闭区间筛选；events 按开始时间/ID 排序，按区间相交筛选。分页默认 20、最多 500；result/points/events 在成功前统一返回 409 RESULT_NOT_READY。历史查询可按站点/管段/状态筛选，详情始终使用任务原快照，不随当前页面对象切换而覆盖。

## 主要错误

| 状态 | code | 处理 |
|---|---|---|
| 422 | INVALID_REQUEST | 核对请求体/分页/提交编号，禁止额外参数 |
| 404 | NOT_FOUND | 核对任务、模型版本或数据集 ID |
| 409 | IDEMPOTENCY_CONFLICT | 同编号已用于不同配置；明确新任务才换编号 |
| 409 | TASK_NOT_RETRYABLE / RESULT_NOT_READY | 查询状态，仅允许可重试失败任务；完成后再读取结果 |
| 422 | SOURCE_MISMATCH / TIMEZONE_MISMATCH | 核对本站对象、数据和模型 |
| 422 | TIME_RANGE_INVALID / DATA_EMPTY / DETECTION_LIMIT_EXCEEDED | 修正范围、采样或点数 |
| 422 | DATA_QUALITY_BLOCKED / SAMPLING_INTERVAL_UNSUPPORTED | 核查数据后重新导入，不强行补点 |
| 503 | MODEL_UNAVAILABLE / CAPABILITY_UNAVAILABLE | 核对模型/环境或执行器状态 |
| 任务 error | TASK_INTERRUPTED / MODEL_EXECUTION_FAILED / STORAGE_WRITE_FAILED / SOURCE_SNAPSHOT_CHANGED | 旧任务保留；可重试时创建新任务，不能把查询失败当作执行失败 |
