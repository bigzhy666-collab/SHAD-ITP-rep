# 本地后端计划与仓库模型对照复核

日期：2026-11-09

> 本文保留 M0 复核时的事实和实验结论。随后 M1 已补齐可选字段透传、CSV 采样检查、质量报告与本地持久化，见 [M1 数据接口](本地数据接口说明.md)；下文“当前 M0”指复核当时，不表示 M1 仍未实现。检测任务与原因模型限制继续有效。

## 结论

**计划的技术路线可行，可以继续开发。** FastAPI 本机服务、SQLite 存储、CSV 标准化、后台区间任务以及现有前端的 Word/PDF 导出，都能围绕现有 `StationModel.detect()` 实现，不需要我们训练模型。

但原计划对完整测点、采样周期、质量门控和长区间执行约束写得不够具体。已修订 [本地后端实施计划 V1.1](本地后端实施计划.md)，将下述补项纳入 M1/M2。当前 M0 是可工作的最低八字段接口，**尚不能作为完整现场适用性或全部业务能力验收**。

本轮只修订计划和说明，没有修改模型、服务实现或前端，也没有执行训练。

## 2. 已匹配的设计

| 计划内容 | 对照结果 |
|---|---|
| 本机纯 CPU、无需云端模型服务 | 与现有 numpy/pandas/scikit-learn 推理路径一致；独立 Python 环境已实际加载成功 |
| 我们只加载模型，模型提供方交付本站产物 | 与每站正常行为模型的适用边界一致，不要求我们改造训练入口 |
| 站点、数据集、模型、版本、时区绑定 | 必要；模型不能直接从管段名称推断适用性 |
| CSV 单位转换和半小时标准化放后端 | 必要；detect() 本身不执行 CSV 单位换算或重采样 |
| 分数/阈值/持续性计数生成数值异常事件 | 与实际输出一致；health 不作为原因概率 |
| 独立连续块重置计数 | 合理的缺口处理策略，但属于后端明确的执行约定，应保存版本，不是原模型自动识别缺口 |
| 先报告持久化，再单独接原因能力 | 可行；报告存储不要求模型生成文本，现有前端可继续生成 Word/PDF |

## 3. 必须补齐的事项

### 3.1 保留模型可用的可选测点

模型卡除了八个核心字段，还允许回水温度设定值、生活热水和储水箱温度等。当前适配器的 values 恰好限制为八字段，这足以完成最低输入测试，但会拒绝已有可选测点。

实际训练特征包括 `err_return`、`err_dhw`、`err_storage_upper` 和 `storage_delta`，这些依赖六个可选原始温度/设定值。可选值缺失时模型可使用训练均值；已有可选值却在导入时丢弃，会改变输入语义。

已补入 M1/M2：核心八字段保持必需，增加受控可选字段、映射和单位支持，内部构造完整 DataFrame，明确哪些测点被模型使用；不能把任意压力、阀位或状态列都宣称成当前 phys2 的模型输入。暂时保留最低接口，不在审核阶段擅自改变 HTTP 行为。

### 3.2 小时级数据不能无条件视为可检测

模型卡描述可接收 10 分钟到 1 小时采样，但当前预处理“半小时均值、删除全空 bin”和后端“缺口分块”结合后，只有整点的小时采样会变成一个点一个块，criticality 每次从 0 开始。

合成核查中，60 个小时点全部 alarm=true，但产生 60 个块，最大 criticality=1、确认事件=0。这个结果不能向用户解释为系统正常。

已补入 M1：记录采样周期与连续覆盖；小时级来源若无经验证的标准化策略，允许存储查看但阻止正式检测。不能擅自插值来制造连续异常证据。短块不足以达到 cThr 时提示确认上下文不足。

### 3.3 质量检测不等于已经自动降级

`quality.py` 有传感器体检和降级辅助函数，实验脚本会使用它们；但当前 `StationModel.detect()` 没有调用这些函数，阈值函数只按室外温度及已保存分箱查值。

因此模型卡关于坏室外传感器自动回退全局阈值的表述，不能直接当作当前产物推理入口的保证。也不能在已训练的固定维度 MLP 上删掉特征，却继续使用原权重和归一化数组。

已补入 M1：质量报告和检查窗口必须可追溯，首版对可靠判定的关键室外传感器问题阻断正式检测；需要降级时，使用模型提供方验证的产物或策略，并保存独立版本。设定值长期不变、夏季停运与短窗口取值少，不能简单视为传感器损坏。

### 3.4 长区间不能靠盲目拆批绕过限制

当前同步接口最多 5000 点，ModelService 的输入校验同样受这个上限约束。后续后台任务不能直接称为“任意长区间”，也不能把大任务拆成多次无状态 detect() 再简单拼接。

原因是每次调用会重置 criticality，且 `stuck_score` 等依赖滚动窗口；缺失室外温度时，阈值选择还可能依赖该调用范围内的室外温度统计。

已补入 M2：首版任务也明确限制 5000 点；更长范围先提示缩小。未来确需分批，必须验证状态、上下文及阈值语义等价。先完成批次检测，不把反复调用无状态函数宣称为实时连续推理。

### 3.5 不把推理自适应当成自动训练或重新标定

当前 adaptive 使用产物保存的 edges、thr_map 和 thr_global。推理会按输入工况查表，不会基于新上传 CSV 自动重新学习本站基线，也不会重新标定 cThr。

本站模型、阈值和依赖版本继续由模型提供方交付；这与“我们只接入已训练模型”的新范围一致。

### 3.6 研究结果不能替代原因模型交付

仓库有监督学习脚本及评估结果，但当前没有对应部署产物。脚本最终保存的是二分类模型；18 类故障方向实验准确率约 0.142，并不提供已验证的具体根因和解决方案生成能力。

因此 M4 保持单独交付条件，不能因为仓库出现“监督模型”“故障类型”字样就提前开启 causeDiagnosis。

## 4. 实际核查记录

以下均使用仓库已有产物和合成输入，只说明接口/执行语义，不是现场性能、模型准确率或国内迁移验证。

| 核查 | 观察结果 | 说明 |
|---|---|---|
| 六个可选测点有值与缺失分别直接推理 | 60 点样例 score 的最大绝对差约 16.9644 | 可选字段会影响结果，不能在导入中丢弃 |
| 60 个连续半小时点拆为两个 30 点调用 | 原第 31 点 criticality=31，第二调用首点变成 1；score 最大绝对差约 3.9345 | 简单拼接不等价 |
| 60 个小时点经当前后端分块 | alarmPointCount=60，blockCount=60，confirmedPointCount=0，eventCount=0 | 需区分“不足以确认”和“正常” |
| 200 点室外温度固定为 5 degC | quality.py 判 constant、outdoor_ok=false；detect() 仍使用 adaptive=true 的阈值 11.092751，全局阈值为 14.132814 | 质量门控没有自动进入该推理入口 |

可复核方法：使用 `backend.example_request.example_request()` 构造 60/200 点样例，经 `prepare_frame()` 得到标准化 DataFrame；直接对原始/增补可选列/切片分别调用同一 model.detect()；小时样例通过现有 ModelService.infer() 运行；质量样例另调用 assess_frame() 和 outdoor_ok() 对照。全程不调用 fit() 或 train_station_model()。

## 5. 继续开发的条件

可以立即开始 M1 的数据库和导入开发，无需推翻现有前端或更换技术栈。正式检测能力开启前需完成本次补项及 M2 的持久化、幂等和恢复验收；面向国内站点发布前仍需模型提供方交付本站产物、确认时区与验证数据。完整 AI诊断还需独立原因能力交付。
