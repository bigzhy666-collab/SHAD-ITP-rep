# SHAD 本地数据接口说明

版本：M1 数据接口（M3 更新）· 服务 0.5.0 · 数据库 schema 3 · 2026-11-09

## 已完成的范围

本机服务已支持组织新增/查询、换热站登记、可信模型登记恢复、CSV 原文件保存、标准化采样和质量报告。前端“本机服务”模式已真实接通换热站登记、字段映射、文件导入、历史数据集和监测曲线；不读取演示采样作为真实记录。

当前 runtime 开启 dataImport/anomalyDetection/offlineDetection/reportPersistence；具体原因诊断仍关闭。M2 检测任务和真实历史/结果已经接入，详见 [检测任务接口](本地检测任务接口说明.md)。同步模型接口仍可单独验证，不自行创建历史。

## 本机启动和查看

在项目根目录执行，需 Python 3.12；首次安装依赖后可离线使用：

```powershell
python -m venv .venv-backend
.\.venv-backend\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
npm run build
.\.venv-backend\Scripts\python.exe -m backend --serve-frontend
```

打开 `http://127.0.0.1:8765/networks`，右上角选择“本机服务”：

1. 选择现有企业→管网→管段，点“确认选择”。展开“登记换热站”，填写站名、编码并绑定。
2. 选择 CSV，确认时间列、八个必需字段、可选字段及原始单位，再执行导入。
3. 查看真实返回的质量说明；从历史数据集进入“查看采样与检测”，点击“读取监测数据”。本站模型已登记且数据/范围合格时，可以创建真实检测。没有适用模型时按钮仍禁用。
4. 关闭后端后重新执行启动命令；站点、数据集和采样从同一数据库恢复，不需要再次上传。

开发方式使用 `--dev-origin http://127.0.0.1:5173` 配合 `npm run dev` 的代理。示例模型须显式指定可信注册表，建议使用独立测试目录；不会自动给新站点分配其他站的模型。

## 数据目录与数据库

默认 `backend/data/`，可用 `--data-dir "D:\SHAD-data"` 或环境变量 `SHAD_DATA_DIR` 指定。优先级：命令行 > 环境变量 > 默认目录。SQLite、原始文件和日志统一在此目录：

```text
数据目录/
  shad.sqlite3        组织、站点、模型登记、数据集元数据和标准化采样
  shad.sqlite3-wal    SQLite 运行时事务文件（可能存在）
  shad.sqlite3-shm    SQLite 运行时共享文件（可能存在）
  sources/<UUID>.csv  原始 CSV，文件名由服务生成，不采用上传路径
  logs/service.log   轮换日志
```

启用 schema_migrations、外键、WAL、5 秒 busy_timeout；M2 自动从 schema 1 迁移到 2，检测结果也保存在 SQLite；拒绝用旧版服务打开更高版本数据库。上传先完整保存独占创建的原文件并 fsync，再在同一数据库事务提交元数据与采样；失败回滚，不返回虚假 ready。启动仅清理超过 24 小时、无数据库引用且符合服务 UUID 名称的孤立 CSV，避开符号链接与其他文件。

模型登记按 `(id,version)` 不可覆盖；站点与时区也不能被后续注册表覆盖。可信注册表登记后保存在数据库，重启不传注册表仍保留。模型文件仍位于 `ml/models/`，校验及可信来源要求见模型接口说明。

当前只提供新增/查询，不提供删除、组织改名、站点迁移、数据库修复或运行中备份接口。备份时停止服务并复制整个数据目录；恢复时保留对应模型文件及依赖环境。安装包、自动备份和升级流程在 M5 实施。

## 公共约定

- 成功：`{"requestId":"...","data":{...}}`；失败：`{"requestId":"...","error":{"code":"...","message":"...","retryable":false,"details":[]}}`。
- 仅本机访问；写操作检查 Origin。浏览器不直接上传或选择任意 pickle 文件。
- 分页默认 page=1、pageSize=20，pageSize 上限 500；返回 `{items,page,pageSize,total}`。
- 请求体通常上限 5 MiB；仅导入接口允许总 multipart 21 MiB，其中 CSV 最大 20 MiB、manifest 文本最大 64 KiB。UTF-8/BOM；不接受 Excel 二进制文件或压缩包。
- 时间采用带偏移 ISO8601；未知值为 null，不发送 JSON NaN/Infinity。质量标记为 valid / missing / invalid。

## 组织和换热站

| 方法与路径 | 请求/用途 | 返回 |
|---|---|---|
| GET `/api/organizations` | 全部组织树 | `{enterprises,networks,segments}`，各为数组，含稳定 id、name、code、active 及所属 id |
| POST `/api/enterprises` | `{name,code}` | 201，新增企业 |
| POST `/api/networks` | `{name,code,enterpriseId}` | 201，新增管网 |
| POST `/api/segments` | `{name,code,networkId}` | 201，新增管段 |
| GET `/api/stations?segmentId=seg-1` | 按管段筛选，可分页 | 本站对象列表 |
| POST `/api/stations` | 见下方 JSON | 201，含生成 id 的站点 |
| GET `/api/models?stationId=...` | 管理员登记模型查询，可分页 | 只读参数、版本、实际可用性 |

```json
{
  "name":"1号换热站",
  "code":"ST-001",
  "enterpriseId":"ent-1",
  "networkId":"net-1",
  "segmentId":"seg-1",
  "timezone":"Asia/Shanghai"
}
```

层级必须存在且完全匹配；编码在同企业下不区分大小写唯一；时区须为合法 IANA 名称。当前界面新站为 Asia/Shanghai，模型时区由管理员确认。初始组织仅为与已有前端对象对应的层级框架，不含站点、运行数据、模型绑定或故障结论。组织新增 API 已实现；本机界面仍使用现有前端的层级选择，自定义新增组织的独立维护/同步界面后续接入，不能把演示组织维护当作真实后端写入。

## 导入 CSV

`POST /api/datasets/import`，multipart **恰好两个字段**：`file` 为文件，`manifest` 为 JSON 字符串。成功保存返回 201；数据质量 invalid 也属于已保存，须检查 data.status，不能只看 HTTP 成功状态。

```json
{
  "name":"1号站运行数据",
  "stationId":"实际站点ID",
  "timezone":"Asia/Shanghai",
  "encoding":"utf-8-sig",
  "delimiter":",",
  "timeColumn":"时间",
  "columnMapping":{
    "室外温度":"outdoor_temperature",
    "一次供温":"p_net_supply_temperature",
    "一次回温":"p_net_return_temperature",
    "瞬时功率":"p_net_meter_heat_power",
    "瞬时流量":"p_net_meter_flow",
    "二次回温":"p_hc1_return_temperature",
    "二次供温":"s_hc1_supply_temperature",
    "二次供温设定":"s_hc1_supply_temperature_setpoint"
  },
  "sourceUnits":{
    "outdoor_temperature":"degC",
    "p_net_supply_temperature":"degC",
    "p_net_return_temperature":"degC",
    "p_net_meter_heat_power":"W",
    "p_net_meter_flow":"m3/h",
    "p_hc1_return_temperature":"degC",
    "s_hc1_supply_temperature":"degC",
    "s_hc1_supply_temperature_setpoint":"degC"
  }
}
```

映射方向为 **原始 CSV 列名 → 标准字段**；单位键为标准字段。delimiter 仅逗号/分号，encoding 仅 utf-8/utf-8-sig。列名唯一、不为空、列数一致、支持规范引号转义；映射不得复用原列或时间列。温度只接受 degC；瞬时功率 W/kW/MW 转 kW；瞬时流量 L/h/m3/h 转 L/h，不接受累计 kWh 或猜测物理侧别。

八核心字段见上例。以下六项均可选、单位 degC；文件已有标准字段名时前端自动匹配，可手动取消；选用时也必须声明对应 sourceUnits：

| 标准字段 | 含义 |
|---|---|
| p_hc1_return_temperature_setpoint | 二次侧回水温度设定值 |
| s_dhw_supply_temperature | 生活热水供水温度 |
| s_dhw_supply_temperature_setpoint | 生活热水供水温度设定值 |
| s_dhw_upper_storage_temperature | 储水罐上部温度 |
| s_dhw_lower_storage_temperature | 储水罐下部温度 |
| s_dhw_upper_storage_temperature_setpoint | 储水罐上部温度设定值 |

已映射的可选列会保存并透传给模型。未提供时由模型使用已保存训练均值补值；不伪造测量值。模型必需字段不存在的可解析 CSV 可保存为 invalid；格式无法解析、非法单位/映射/时区则 422，不创建数据集。

每次成功导入建立独立不可变数据集，version 为字符串 `1`；重复上传当前不去重，也不覆盖旧记录。保存 SHA-256、原单位、映射、创建时间及预处理版本 `csv-utf8-units-30min-quality-v1`，方便追溯。

## 标准化和质量报告

1. 时间须包含完整日期和时分；无偏移时间按站点时区解释，带偏移时间转入站点时区。不存在/含糊时间排除并计数；相同时间保留文件中第一行，再稳定排序。
2. 越界温度（小于 -60 或大于 220℃）、负功率/流量、非数值或非有限值置 null 并标 invalid；空白标 missing。保留各列和问题计数。
3. 30 分钟左闭右开 bin 求均值，仅处理实际占用的 bin；不跨缺口填充或插值。全空 bin 不纳入采样；某 bin 有有效和无效原值混合时保留有效均值，同时质量仍标 invalid，提示核查。
4. 缺少核心列、无有效点、核心整体或任一连续块缺失超过 80%、夏令时重复墙上时间，均标 invalid。原始文件和可读问题仍保留。
5. 来源时间间隔中位数超过 30 分钟，标 `SAMPLING_INTERVAL_UNSUPPORTED` 并阻断正式检测；可以查看小时采样，不能将没有累积确认告警解释成正常。
6. `sampling` 保存 sourceMedianMinutes、normalizedMinutes=30、blockCount、maxBlockPoints、expectedBinCount、occupiedBinCount、coverageRatio。覆盖率为实际保留 bin / 首末物理时间间隔内期望 bin，不代表所有测点有效率。M2 创建任务时已按模型 cThr 提示短连续块，不把无法确认当作正常。
7. 每个至少 145 点（72 小时）的连续块只读调用仓库 `quality.py`。保存 `sensorQuality` 的检查策略、已检查/不足窗口块数、字段结论和原因；短窗口明确提示，不据此判定长期冻结。设定值常值和功率零负荷遵从原质量规则，不视作坏传感器。
8. 已检查窗口内严重室外测点问题标 `OUTDOOR_SENSOR_UNHEALTHY` 并阻断；不删除已训练特征、不修改自适应开关，也不假装已实现全局阈值自动降级。质量规则是核查提示，不是具体故障原因。

ready 只表示当前数据门槛通过，不表示存在适用模型、已完成检测、状态正常或可确认具体故障。M2 已按所选范围重新校验质量标记/核心缺失、采样周期、传感器质量、站点、模型版本、时间和最多 5000 点约束；低层同步推理不会替调用者执行本数据导入流程。

## 查询数据和标准化采样

| 路径 | 参数/返回 |
|---|---|
| GET `/api/datasets` | stationId 可选，按创建时间倒序分页；返回完整质量摘要 |
| GET `/api/datasets/{id}` | 返回导入响应的完整数据集元数据、映射、单位、质量与采样报告 |
| GET `/api/datasets/{id}/samples` | start、end 为可选带时区 ISO8601；闭区间；同时提供时 start < end；fields 为逗号分隔标准字段，可分页 |

采样始终按物理时间升序。values 与 quality 使用同一字段集合；未导入的白名单字段查询返回 null/missing。重复/未知字段与无时区的查询时间返回 422；不存在的数据集返回 404。

```json
{
  "items":[{
    "timestamp":"2026-11-08T00:00:00+08:00",
    "values":{"p_net_meter_flow":12000},
    "quality":{"p_net_meter_flow":"valid"}
  }],
  "page":1,"pageSize":20,"total":1
}
```

主要错误：400 INVALID_REQUEST（上传表单）、409 STATION_CODE_CONFLICT / ORGANIZATION_CONFLICT、413 REQUEST_TOO_LARGE、422 SOURCE_MISMATCH / TIMEZONE_MISMATCH / UNIT_UNSUPPORTED / CSV_FORMAT_INVALID / TIME_RANGE_INVALID、500 STORAGE_WRITE_FAILED、503 STORAGE_UNAVAILABLE。保存错误明确反馈，不将失败导入列为可用数据。
