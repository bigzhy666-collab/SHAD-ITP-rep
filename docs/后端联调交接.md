# SHAD 前端与本机后端联调交接

日期：2026-11-08

## 当前交付状态

前端已提供独立的“演示模式”和“本机服务”模式；右上角切换，模式偏好保存在本机浏览器。现有四模块演示保留，本机模式不会读取演示任务作为真实任务，也不会在 API 失败时回退演示结果。

**本仓库当前没有本机 HTTP 后端。**本轮完成前端界面、调用代码和契约测试，未运行真实 Python 模型联调。浏览器测试中的 `/api` 由测试框架拦截，测试数据有“接口联调模型（非真实推理）”标识；这不能作为模型验收结果。

双方依据 [本机接口约定](本机接口约定.md) 实现和验收。前端实际类型见 [types.ts](../src/services/local/types.ts)，调用方法见 [api.ts](../src/services/local/api.ts)。本说明补充已经采用的前端行为和 P1 数据结构，不改变模型的能力边界。

## 1. 开发与正式运行

开发环境：

1. 后端在本机启动服务，推荐开发地址 `http://127.0.0.1:8765`。
2. 地址不同则复制根目录 `.env.example` 为 `.env.local`，修改 `SHAD_BACKEND_URL`。只支持本机 HTTP/HTTPS 地址；此配置仅供开发代理使用，不是浏览器直接访问外部服务器的地址。
3. 前端运行 `npm install`、`npm run dev`，访问终端给出的页面地址；选择“本机服务”。
4. `/api` 由 Vite 转发到本机后端。修改环境配置后需重启前端开发服务。

正式运行：

- 运行 `npm run build`，由本地后端提供 `dist` 的静态资源，前端路由回退到 `index.html`，API 仍使用同源 `/api`。
- `/api` 不得回退为 index.html；找不到接口时返回规范 JSON 错误和相应 HTTP 状态。
- 保留 `fonts/NotoSansSC.ttf`、SHAD 标识及所有构建资源，不依赖字体 CDN 或云端模型服务。
- Vite 的 `npm run preview` 只用于查看构建结果，不提供本轮开发代理，也不能代替正式软件的本地后端。
- 安装包、后端启动程序、Python 运行环境和数据存放目录由后端/打包阶段交付；前端未实现系统安装器。

## 2. 建议后端交付顺序

### 第一批：连接与元数据

提供 `/runtime`、`/stations`、`/models`、`/datasets`。前端以 `contractVersion: "1.0"` 和 `mode: "local"` 判断兼容性，capabilities 必须是真实布尔值。未实现原因诊断或报告存档时分别返回 false。

企业、管网、管段注册表需与本地前端 ID 对齐。当前已有组织 ID 可在 `src/services/demo.ts` 的 `seedWorkspace()` 中查看；这里只复用组织标识，不将其中采样、异常、原因作为真实数据上传。后续统一组织接口可另行扩展，当前不可宣称组织维护已全量接入后端。

`GET /stations?segmentId=...` 应只返回当前管段绑定的站点；一个绑定自动选择，多个绑定由用户明确选择。`/models` 和 `/datasets` 按 stationId 筛选。前端登记站点使用 `POST /stations`，时区暂固定 Asia/Shanghai；非北京时间的历史站可查看旧结果，但当前新检测表单不支持其时间输入。

### 第二批：导入与实际检测

提供文件导入、采样读取、任务创建/查询/重试、结果摘要、逐点结果和事件列表。前端已完成：

- UTF-8 CSV 预览：逗号/分号、BOM、引号与换行、列数校验、重复表头校验。
- 首期预览限制 20 MB；大文件先拆分。后端仍需独立限制与校验文件，不能信任前端验证。
- 必须完整确认时间列与八个测点；一个原始列只能使用一次。标准字段名可以预填，含糊中文列名不会擅自推断。
- 流量 L/h 或 m³/h，热功率 W/kW/MW；前端发送原始单位，由后端转换、重采样和质量校验。
- 展示原始预览与标准化采样。读取/CSV 导出遍历全部分页，失败停止，不把部分数据标作完整。
- 模型配置只读，选择图表参数不会删减模型输入。
- 检测任务 queued/running/success/failed，只显示实际阶段，不使用浏览器计时器模拟完成或百分比。
- 综合分数/阈值曲线、确认事件勾选与定位、全量逐点/事件 CSV、无异常成功和失败重试。
- 稳定事件 ID 的选择作为 UI 偏好保存，刷新与从报告返回后恢复；任务和结果本身仍以本机后端为准。

前端默认每页请求 500 条，但按响应中的实际分页继续读取，不假定后端必须每页返回 500 条。任务和报告快照必须不可变，不能返回按当前全局管段拼出来的结果。

### 第三批：原因诊断与报告持久化

只有能力开启时，前端才调用对应接口。不是由当前异常检测模型自然推导出来的能力，后端必须另行实现和验证。

原因诊断采用以下响应 data 字段；外层 requestId/data/error 与公共约定一致：

| 字段 | 类型与含义 |
|---|---|
| id / detectionId | string；诊断 ID、来源检测 ID |
| eventIds | string[]；所选的同一任务事件 |
| status | queued / running / success / failed |
| phase | 实际阶段的文字或约定代码 |
| error | null 或公共 Failure 对象 |
| steps | `{title, summary, state, evidence: string[]}`[]；state 为 pending/running/done/failed |
| observations | string[]；实际观测摘要 |
| hypotheses | `{title, evidence, confidence: number \| null}`[]；没有依据时 confidence 必须 null |
| recommendations | `{title, action, verification}`[]；建议及复核方法 |
| limitations | string[]；数据或模型局限 |

未产生的数组返回空数组，不能省略为 undefined。`GET /diagnoses` 按通用分页结构返回诊断；`POST /diagnoses` 接受 `{detectionId,eventIds}` 和 Idempotency-Key。新建后使用 `/diagnosis/{id}` 路由恢复轮询；阶段文本来自实际后端，前端不生成“深度思考”。失败后保留旧任务，允许新建诊断；重试创建使用新请求键。

报告响应 data 字段：

| 字段 | 类型与含义 |
|---|---|
| id / title / detectionId | string |
| diagnosisId | string 或 null，检测阶段报告允许为空 |
| eventIds | string[]；本报告的选定事件 |
| version | number；历史版本号，从 1 开始 |
| revision | number；备注/归档的并发修订号，每次写入增加 |
| createdAt / archivedAt | ISO 时间，archivedAt 未归档时为 null |
| note | string，空备注使用空字符串 |
| snapshot | `{task, result, events, points, diagnosis}`；diagnosis 可空，其余类型与检测接口相同 |

要求：

- `POST /reports` 原子生成快照，eventIds 与 snapshot.events 一致，task/result/points 均属于同一检测任务。diagnosis 非空时必须属于该任务及相同的事件选择。
- 快照 points 包含该任务完整范围分数，events 只包含所选事件，避免混入其他事件的结论。
- `GET /reports` 返回分页报告记录，可包括完整快照；首期前端直接使用该结构。大量历史数据时可另约定摘要结构，不能单方面删字段。
- 保存备注、归档、新版本都返回完整更新后的 Report；revision 冲突为 409。新版本复制快照和备注，archivedAt 置 null，返回新 ID。
- 归档后不能修改备注；导出读取当前保存版本。前端不会在导出时自动伪造“已归档”状态。
- 前端在保存的报告版本上有未保存备注时，导出前先提交备注；保存失败不继续导出成“已保存”版本。
- 全局刷新保留未保存备注，避免后台数据更新覆盖用户输入；写入时仍使用原 revision 处理冲突。

## 3. 无报告后端时的前端行为

`reportPersistence: false` 不阻止查看检测结果和下载阶段报告：

- 从检测单选或多选确认告警，进入 AI诊断页核查证据。
- 原因诊断能力为 false 时，按钮禁用并解释原因。报告不会出现演示 causesFor 的故障原因、置信度或措施。
- 可填写备注并真正生成 Word/PDF，读取同一份前端临时快照，含对象、事件、模型和数据版本、分数曲线与能力说明。
- 临时报告版本为 0，ID 前缀为 LOCAL，明确“未存档”；保存、归档按钮禁用。备注仅在当前页面有效，关闭页面不承诺恢复。
- 图表导出使用独立完整尺寸，不受手机宽度和页面缩放影响。

## 4. 重复提交、错误与恢复

- 创建检测、重试、诊断、报告均使用 Idempotency-Key。未收到确定成功前，前端在 localStorage 保存请求内容与键；同一请求重发复用键，成功后清理。无法保存请求键时阻止提交。
- 后端仍必须执行幂等。此机制不是仅靠按钮禁用来保证；页面刷新或响应丢失后依然需要后端返回原任务。
- 连接失败、错误 JSON、接口返回 HTML、服务契约不匹配均单独提示。真实模式不自动切回演示。
- 超时不等于任务失败，先恢复查询；查询 404 等确定错误不持续轮询。执行中任务按实际返回继续查询。
- 前端核对结果的 detectionId、事件 detectionId/stationId；来源错误时停止展示。后端仍须完整校验和保存来源关系。
- 字体读取/PDF 生成失败保留表单，可重试；本地后端的保存失败不能提示归档成功。
