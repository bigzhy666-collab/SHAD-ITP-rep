# 模型卡：换热站正常行为模型

## 用途

判断一个换热站当前的运行状态是否偏离本站正常水平，在客户报修之前给出预警。模型有两种形态：一是无监督的正常行为模型，每站单独训练，不需要故障标签；二是可选的跨站监督模型，用历史工单训练，输出故障概率，作为复核和故障方向建议。

模型只覆盖换热站站内设备与控制系统（阀门、水泵、控制参数、换热器、传感器），不覆盖埋地管道本体。

## 输入

以下字段为必需项：

| 标准字段 | 含义 | 单位 |
|---|---|---|
| outdoor_temperature | 室外温度 | ℃ |
| p_net_supply_temperature | 一次侧供水温度 | ℃ |
| p_net_return_temperature | 一次侧回水温度 | ℃ |
| p_net_meter_heat_power | 瞬时热功率 | kW |
| p_net_meter_flow | 瞬时流量 | l/h |
| p_hc1_return_temperature | 二次侧采暖回水温度 | ℃ |
| s_hc1_supply_temperature | 二次侧采暖供水温度 | ℃ |
| s_hc1_supply_temperature_setpoint | 供水温度设定值 | ℃ |

可选字段有生活热水供水温度及其设定值、储水箱上下部温度及设定值、一次侧回水设定值、阀门开度、水泵状态、控制单元模式，有则使用，缺失时留空（特征里对应列缺失，模型用训练均值填补）。

对数据质量的要求：采样间隔 10 分钟到 1 小时，内部统一重采样到 30 分钟；训练期至少连续 30 天正常运行数据，建议三到六个月并覆盖采暖季和非采暖季；单列缺失超过 80% 会被自动剔除；不要跨大缺口插值；累计量表（电量、体积）不参与建模。

## 输出

调用 `detect(df)` 返回逐时间点的表，包含：异常分数 `score`、该点阈值 `threshold`（工况自适应时随室外温度变化）、点级是否超阈 `alarm`、持续性计数 `criticality`、健康度 `health`（1 减去分数除以阈值，截断到 0 到 1）、以及最终是否达到持续性阈值的 `confirmed`。配套的 `segments()` 把连续告警合并成段，给起止时间、持续小时、峰值分数和最大计数。

## 使用

```python
from src.inference import train_station_model, save_model, load_model

model = train_station_model("M1", 7, train_end="2017-11-12", feature_mode="phys2",
                            cyclic=True, adaptive=True, c_thr=7)
save_model(model, "models/M1_s7.pkl")

model = load_model("models/M1_s7.pkl")
res = model.detect(df)              # df 需要是 DatetimeIndex + 上面必需字段
alarms = res[res["confirmed"]]
```

命令行也可以：

```
python scripts/train_station_model.py --mfr M1 --sid 7 --start 2015-04-12 --end 2017-11-12 --out models/M1_s7.pkl
python scripts/score_station.py --model models/M1_s7.pkl --mfr M1 --sid 7 --start 2017-11-18 --end 2017-11-27
python scripts/score_station.py --model models/M1_s7.pkl --csv 某换热站.csv --time-col 时间 \
    --map "供水温度=s_hc1_supply_temperature" "回水温度=p_hc1_return_temperature" "室外温度=outdoor_temperature"
```

`models/M1_s7.pkl` 是训练好的示例：用 M1 站 7 在 2015-04-12 到 2017-11-12 的数据训练，在 2017-11-22 05:00 触发确认告警，对应客户报修 2017-11-26，提前 4.3 天。

## 性能

按 PreDist 论文协议评估，115 个事件（故障 50、正常 65）：

- 无监督最终配置：正常时段点级准确率 0.990，事件级 F0.5 0.780，报修前检出率 58%，平均提前 3.75 天；
- 监督窗口模型：F0.5 0.833，检出率 58%，平均提前 4.73 天（需要历史工单）；
- 论文摘要报告的水平是 0.98 / 0.83 / 60% / 3.9 天，与本文结果处于同一量级，检出率略低。

分厂商看，M1 的 F0.5 是 0.833、检出率 0.654，M2 是 0.714 和 0.500，M2 的差距主要来自传感器质量和工况差异。

## 训练成本

单站单模型 5 到 8 秒，纯 CPU，不需要 GPU 和深度学习框架。整轮协议实验（115 个事件）7 分钟左右，跨站监督模型两三分钟，内存不超过 2 GB。

## 适用边界

适用：换热站内设备与控制系统的状态异常，包括阀门卡涩、水泵故障、控制参数配错、换热器泄漏、传感器冻结、生活热水异常这几类。

不适用，需要另一条技术线：埋地管道本体缺陷（腐蚀、减薄、裂纹）要用声发射或超声检测；泄漏点定位要用负压波、分布式光纤或示踪气体；管道结构安全评估需要应力和土体腐蚀数据。

## 迁移与部署

部署方式是每站用本站历史数据重新训练，30 天数据就能冷启动，不需要故障标签；德国的数据用来验证方法和评估协议，训练结果不能直接用于国内站点。

落地需要做三件事：把国内热力公司的字段映射到标准字段（`src/inference.py` 里内置了供水温度、回水温度、瞬时流量、瞬时热量、室外温度等常见中文列名）；把单位换成 kW、l/h、℃；用本站训练期分布重新标定阈值和持续性阈值（`adaptive=True` 会自动做）。

与国内工况的已知差异包括：一次网温度更高（110 到 130 度）、供暖期集中、部分站点没有生活热水储水箱、测点更少（可能缺设定值和阀门开度）。

## 风险

训练期混进故障或维修会让模型把错误行为学成正常。训练前会自动剔除扰动前后各 4 小时，但建议人工确认训练期的截图。

季节外推会带来误报，比如用冬季数据训练、夏季检测。缓解办法是训练期覆盖完整年周期，并启用循环时间特征。

室外温度传感器故障会让自适应阈值失效，M2 有多个站属于这种情况。模型里已经加了质量检查，异常时退回全局阈值。

故障类型细分目前不可用（18 类准确率 0.142），只作为候选方向提示。

阈值和超参在同一批事件上交叉验证标定，没有独立测试集，存在过拟合风险，上线后建议按月复盘再标定。

累计量表存在计数器归零（相邻步长有 35% 不是递增），已经从特征里剔除。
