# 换热站状态预测模型研发报告

模型用换热站的运行数据建立正常行为基线，在客户报修前发现设备与控制异常。评估协议与数据问题的细节见[基线方法与评估协议](文献/基线方法与评估协议.md)，对外使用说明见[模型卡](模型卡.md)，方案层面的表述见[技术方案](技术方案-模型章节.md)。

## 一、任务

用换热站的运行时间序列判断站点当前状态是否偏离"本站正常"，在客户报修之前给出预警，并输出异常分数、告警时刻和提前量。数据来源是德国 Fraunhofer IEE 公开的 PreDist 数据集：93 个换热站，2012 到 2020 年，原始采样 10 分钟，统一重采样到 30 分钟；标签是客户报修工单和人工挑选的正常时段。

数据对象需要先明确：这套数据是换热站站内设备与控制系统的数据，不是埋地管道本体。模型能覆盖阀门、水泵、控制参数、换热器、传感器这几类故障，不覆盖管壁腐蚀、管道泄漏定位这类需要声发射或负压波的检测，那是另一条技术线。

## 二、评估协议

评估沿用原论文的协议，这样结果才能和论文的 0.98 / 0.83 / 60% / 3.9 天比较。要点是每个事件单独训练一个正常行为模型，而不是训练一个全局模型：

- 异常事件：只取 `efd_possible` 为真、训练区间不少于 14 天、同站同类故障只留第一次报修的事件；
- 训练集：`Training start` 到 `Training end`，并剔除故障段和训练区间内的维修扰动；
- 测试窗：异常事件取报修前 7 天，终点就是报修时刻；正常事件取 `Event start` 到 `Event end`；
- 点级判决：异常分数超过训练分数 99% 分位就认为异常；
- 持续性判据：用 criticality 计数器（超阈值加一、否则减一、维修期间不变），计数最大值达到 `C_thr` 才判该事件检出，`C_thr` 在 1 到 100 上做 5 折交叉验证、按 F0.5 选；
- 指标：正常时段点级准确率 A、事件级 F0.5、报修前检出率、Earliness（提前量按 24 小时归一）、平均提前天数。

本次实验共 115 个事件，故障 50 个（M1 26、M2 24），正常 65 个（M1 35、M2 30），没有跳过的事件。M1 和 M2 分开标定阈值、分开报告，因为两家的特征集、序列长度和最优异常分数都不同。

## 三、实验配置

技术设计（物理残差特征、工况自适应阈值、传感器体检与降级）见[技术方案](技术方案-模型章节.md)第二、三节，这里只记录每次实验使用的配置。

基线：原始测点经剔除、均值填补、分位裁剪、标准化后输入；自编码器结构为 输入 → 64 → 瓶颈（M1 取 0.65 倍维数、M2 取 0.25 倍）→ 重建，用 sklearn 的 `MLPRegressor` 实现，不依赖 TensorFlow；异常分数 M1 用马氏距离、M2 用 RMSE；输入噪声正则 0.05 / 0.15；最多 100 轮，20% 验证集早停；阈值取训练分数的 99% 分位。单个事件训练 5 到 8 秒，115 个事件约 7 分钟。

改进：特征换成 phys2 紧凑集（约 20 维物理量加循环时间编码），模型结构与阈值机制不变。

监督模型：报修前 6 小时到 7 天的窗口特征（16 个物理量的均值、方差、极值、分位、斜率，共 149 维），梯度提升分类器，按站分组 5 折交叉验证，避免同一个站的数据同时出现在训练和验证里。

传感器体检与跨站预训练的具体设置分别见第六、七节。

## 四、结果

全事件（115 个）的结果：

| 配置 | A | F0.5 | 报修前检出率 | 事件误报率 | Earliness | 平均提前 |
|---|---|---|---|---|---|---|
| 论文摘要（两个厂商合并口径） | 0.98 | 0.83 | 60% | 未报告 | 未报告 | 3.9 天 |
| 论文口径基线（原始测点 + AE） | 0.995 | 0.753 | 44.0% | 3.1% | 0.394 | 3.80 天 |
| 紧凑物理特征（不加自适应阈值） | 0.992 | 0.769 | 56.0% | 7.7% | 0.489 | 3.79 天 |
| 最终配置（M1 自适应阈值、M2 全局阈值） | 0.990 | 0.780 | 58.0% | 7.7% | 0.534 | 3.75 天 |
| 监督窗口模型（跨站，按站分组交叉验证） | 0.995 | 0.833 | 58.0% | 3.1% | 0.525 | 4.73 天 |

分厂商看，最终配置下 M1 是 A 0.988、F0.5 0.833、检出率 0.654、平均提前 4.13 天；M2 是 A 0.994、F0.5 0.714、检出率 0.500、平均提前 3.22 天。M2 明显弱于 M1，原因在第六、七节。

故障类型多分类目前不可用：18 个类别、346 个窗口、按站分组交叉验证，准确率 0.142，Top-3 0.318。主要原因是单类样本太少（多数类别只出现一到三次），跨站分布差异又大。现在只把它当作"给出候选方向"的参考，不作为结论输出。

## 五、消融实验的结论

物理特征不是越多越好。把全部工程特征（60 多列）一起输入时，检出率从 0.44 提到 0.54，但事件误报率从 3% 涨到 12%，F0.5 反而掉到 0.711。原因是维度太高之后自编码器接近恒等映射，重构误差失去区分度；马氏距离在高维下协方差也估不准。压缩到 20 列上下之后，F0.5 回到 0.769，是这批实验里最高的单点配置。

循环时间编码是低成本的稳健收益，加进去 F0.5 从 0.753 到 0.767，几乎不增加训练开销，主要效果是减少季节性误报。

自适应阈值要分厂商看。M1 的室外温度质量好，启用后 F0.5 从 0.816 提到 0.833，检出率从 0.615 到 0.654，Earliness 从 0.539 到 0.625；M2 因为多个站室外温度传感器有问题，启用后 F0.5 掉到 0.625 甚至更低。所以最终没有做成全局开关，而是按厂商选配置，并且加了室外温度质量检查作为前置条件。这个"按厂商选配置"是在同一批事件上选出来的，存在选择偏差，与论文按厂商给配置的做法相同。

短训练窗事件反而更容易检出。原本预期 M2 训练窗只有 20 到 30 天会导致欠拟合，但实际训练窗少于 180 天的 23 个故障事件，基线检出率是 0.696，高于总体 0.440。这说明 M2 的短板不是数据量，而是别的东西（见第六节）。

## 六、传感器体检

基于上一条结论，设计了一套逐站逐测点的体检：缺失率、常值或冻结（连续不变的小时数）、越界、分辨率、尖峰五类判定。规则上有两处需要按测点类型区分，否则误报会很多：设定值和状态量长期不变是正常的控制行为，不做常值判定；流量和功率在夏季停运期长期为 0 属于季节工况，记为 idle 而不是故障。

判定结果：93 个站、1599 个站-测点组合中，正常 1028 个，冻结 245 个，缺失 183 个，噪声 139 个，低分辨率 4 个。其中室外温度是重点，因为自适应阈值依赖它。

用 README 和本地探查记录里人工标注的坏传感器做验证：已知有问题的 6 个室外温度传感器（M1 的 19 号，M2 的 3、18、41、47、61 号），体检全部命中，没有漏报；另外新发现 7 个站存在长时间数值不变（M1 的 5、31 号，M2 的 7、17、21、28、45 号），最长连续不变 74 到 1474 小时，这些人工记录里没有。按"严重到需要降级"的口径统计，有 13 个站需要处理，涉及 10 个评估事件。

降级的做法是：坏传感器及其派生特征一起从特征矩阵里剔除（比如室外温度坏了，依赖它的供暖曲线残差、负荷指数、供暖季标记、缺失率也一起删），同时关闭自适应阈值。把降级接进协议后重跑 115 个事件，指标和"仅按质量门控关闭自适应阈值"完全一致（A 0.988、F0.5 0.737、检出率 0.560），没有回退。该模块在这批评估事件上不体现为分数提升，作用是让坏站的特征矩阵不含错误信号，并产出一份可直接交给运维的传感器健康清单。

还需要区分一种情况：主网温度在夏季连续 29 天不变的有 33 个站，那是停运工况而不是传感器故障。如果按"连续不变就是冻结"一刀切，会误删有效信号，这是做降级时最容易出错的地方。

## 七、跨站预训练实验（负结果）

原本的计划是用其他站的正常数据预训练自编码器，再用目标站的数据微调，以此解决 M2 训练窗太短的问题。做了两版实现，都没有带来提升。

防泄漏的处理是：给某个站预训练时，把这个站自己的数据从语料库里排除，等价于新站冷启动。语料库来自其余站，去掉首月调试期和维修扰动，每站抽样 6000 行。第一版把语料统一标准化后混合；第二版改成每个站先按自己的统计量标准化再混合，并把微调加强到 60 个 epoch、学习率 3e-4。

结果是第一版全事件 F0.5 0.753、检出率 0.500，第二版 F0.5 0.661、检出率 0.460，都低于不迁移的 0.769 和 0.560。短训练窗子集上同样没有收益：不迁移是 F0.5 0.879、检出率 0.696，第一版 0.824 / 0.652，第二版 0.783 / 0.565。

原因在于站间异质性太强：配置类型、测点集合、供暖曲线量级都不一样，预训练学到的是一个"平均站"，反而把目标站特有的正常模式抹平了；而单站自编码器在 30 维输入、两万行数据下已经拟合得不错，迁移带来的初始化收益抵不过分布不匹配的损失。

这个结果表明每站自学习在这套数据上是更合适的做法。代码保留在 `src/pretrain.py` 和 `scripts/run_pretrain.py`，可以复现。

## 八、目前的局限

产品层面的判断（数据对象、域偏移、M2 短板）见[技术方案](技术方案-模型章节.md)第五节。这里补充研发层面的三点观察：

- 监督模型的指标偏乐观。样本只有 50 个故障事件，正样本来自报修前的固定锚点；加入同站硬负样本后，窗口级 AUC 从 0.93 降到 0.78，报告采用后者的口径。
- 故障类型细分不可用（18 类准确率 0.142、Top-3 0.318），原因是单类样本太少且跨站分布差异大。
- 阈值与超参在同一批事件上交叉验证标定，没有独立测试集，存在过拟合风险；换数据或换特征之后 `C_thr` 必须重新标定。

## 九、文件与复现

代码在 `src/`：数据加载与统一（`data.py`）、特征工程（`features.py`）、评估协议（`protocol.py`）、模型（`models.py`）、传感器体检（`quality.py`）、跨站预训练实验（`pretrain.py`）、模型产物接口（`inference.py`）。实验脚本在 `scripts/`，图表在 `reports/figures/`，各配置的指标 CSV 和 metrics.json 在 `reports/` 对应的实验目录下。

复现主实验：

```
python scripts/run_baseline.py --variant default --out baseline_default
python scripts/run_baseline.py --variant cyclic --features phys2 --out final_phys2
python scripts/run_baseline.py --variant cyclic --features phys2 --adapt-thr --out final_v3_gated
python scripts/run_build_final.py            # 组合最终配置并重算指标
python scripts/run_supervised.py
python scripts/run_quality.py
python scripts/make_figures.py --runs reports/baseline_default:论文口径基线 reports/final_best:最终模型 --out-prefix final2
```

环境用 Python 3.13，依赖 numpy、pandas、scikit-learn、matplotlib，不需要 TensorFlow。监督模型脚本在导入 sklearn 前把线程数固定为 1，既保证可复现，也避开某些环境下多线程后端的进程/管道限制；所有脚本都关闭了 sklearn 的收敛警告，它只表示未完全收敛，不影响结果。
