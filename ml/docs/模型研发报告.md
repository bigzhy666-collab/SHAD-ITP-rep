# 换热站状态预测模型：研发现状说明

这份文档说明模型的现状：用了什么数据、按什么协议评估、模型怎么搭、结果如何、试过哪些不成立的方向、还有什么问题。具体的协议细节和数据坑写在 `文献/基线方法与评估协议.md`，模型卡在 `模型卡.md`，这里只讲研发过程与结论。

## 一、任务

用换热站的运行时间序列判断站点当前状态是否偏离"本站正常"，在客户报修之前给出预警，并输出异常分数、告警时刻和提前量。数据来源是德国 Fraunhofer IEE 公开的 PreDist 数据集：93 个换热站，2012 到 2020 年，原始采样 10 分钟，统一重采样到 30 分钟；标签是客户报修工单和人工挑选的正常时段。

有一点需要先说明：这套数据是换热站站内设备与控制系统的数据，不是埋地管道本体。模型能覆盖阀门、水泵、控制参数、换热器、传感器这几类故障，不覆盖管壁腐蚀、管道泄漏定位这类需要声发射或负压波的检测，那是另一条技术线。

## 二、评估协议

我们按原论文的协议评估，否则结果和论文的 0.98 / 0.83 / 60% / 3.9 天无法比较。要点是每个事件单独训练一个正常行为模型，而不是训练一个全局模型：

- 异常事件：只取 `efd_possible` 为真、训练区间不少于 14 天、同站同类故障只留第一次报修的事件；
- 训练集：`Training start` 到 `Training end`，并剔除故障段和训练区间内的维修扰动；
- 测试窗：异常事件取报修前 7 天，终点就是报修时刻；正常事件取 `Event start` 到 `Event end`；
- 点级判决：异常分数超过训练分数 99% 分位就认为异常；
- 持续性判据：用 criticality 计数器（超阈值加一、否则减一、维修期间不变），计数最大值达到 `C_thr` 才判该事件检出，`C_thr` 在 1 到 100 上做 5 折交叉验证、按 F0.5 选；
- 指标：正常时段点级准确率 A、事件级 F0.5、报修前检出率、Earliness（提前量按 24 小时归一）、平均提前天数。

本次实验共 115 个事件，故障 50 个（M1 26、M2 24），正常 65 个（M1 35、M2 30），没有跳过的事件。M1 和 M2 分开标定阈值、分开报告，因为两家的特征集、序列长度和最优异常分数都不同。

## 三、模型做法

基线和改进都基于同一个框架：用自编码器学正常行为，输入是标准化后的测点，输出是重构，异常分数取重构误差（M1 用马氏距离，M2 用 RMSE），阈值取训练分数的 99% 分位。自编码器用 sklearn 的 `MLPRegressor` 实现（输入到 64、再压到瓶颈、再重建回输入维度），不依赖 TensorFlow，单个事件训练 5 到 8 秒，跑完 115 个事件约 7 分钟。

跟论文基线相比，我们做了三处改动。

第一处是加物理残差特征，但只保留紧凑的一组。原始温度、流量、功率的绝对值随室外温度、季节、昼夜变化很大，直接建模学到的主要是天气。所以我们把工况抵消掉，只留偏离量：一次侧和二次侧的供回温差、实测值减设定值、实际供水温度减去同室外温度下的历史中位数（也就是偏离供暖曲线）、热功率除以温差（流量健康度的代理量）、归一化流量和负荷、24 小时滚动标准差（传感器冻结程度）、短时缺失率。另外加了小时、星期、年内日的 sin/cos 编码来刻画季节和昼夜。

第二处是工况自适应阈值：按室外温度分 5 箱，各箱单独取训练分数的 99% 分位，而不是整站一个阈值。但这条只在室外温度数据可信时启用，否则退回全局阈值。

第三处是传感器体检与降级，见第六节。

监督模型是另一条支线：在有历史工单的前提下，用报修前 6 小时到 7 天的窗口特征（16 个物理量的均值、方差、极值、分位、斜率等，共 149 维）训练梯度提升分类器，做跨站的故障概率预测；按站分组交叉验证，避免同一个站的数据同时出现在训练和验证里。

## 四、结果

全事件（115 个）的结果：

| 配置 | A | F0.5 | 报修前检出率 | 事件误报率 | Earliness | 平均提前 |
|---|---|---|---|---|---|---|
| 论文摘要（两个厂商合并口径） | 0.98 | 0.83 | 60% | 未报告 | 未报告 | 3.9 天 |
| 论文口径基线（原始测点 + AE） | 0.995 | 0.753 | 44.0% | 3.1% | 0.394 | 3.80 天 |
| 紧凑物理特征（不加自适应阈值） | 0.992 | 0.769 | 56.0% | 7.7% | 0.489 | 3.79 天 |
| 最终配置（M1 自适应阈值、M2 全局阈值） | 0.990 | 0.780 | 58.0% | 7.7% | 0.534 | 3.75 天 |
| 监督窗口模型（跨站，按站分组交叉验证） | 0.995 | 0.833 | 58.0% | 3.1% | 0.525 | 4.73 天 |

分厂商看，最终配置下 M1 是 A 0.988、F0.5 0.833、检出率 0.654、平均提前 4.13 天；M2 是 A 0.994、F0.5 0.714、检出率 0.500、平均提前 3.22 天。M2 明显弱于 M1，原因在第六、七节。

故障类型多分类目前做不了：18 个类别、346 个窗口、按站分组交叉验证，准确率 0.142，Top-3 0.318。主要原因是单类样本太少（多数类别只出现一到三次），跨站分布差异又大。现在只把它当作"给出候选方向"的参考，不作为结论输出。

## 五、几次消融得到的结论

物理特征不是越多越好。我们把全部工程特征（60 多列）一股脑塞进去时，检出率从 0.44 提到 0.54，但事件误报率从 3% 涨到 12%，F0.5 反而掉到 0.711。原因是维度太高之后自编码器接近恒等映射，重构误差失去区分度；马氏距离在高维下协方差也估不准。压缩到 20 列上下之后，F0.5 回到 0.769，是这批实验里最高的单点配置。

循环时间编码是低成本的稳健收益，加进去 F0.5 从 0.753 到 0.767，几乎不增加训练开销，主要效果是减少季节性误报。

自适应阈值要分厂商看。M1 的室外温度质量好，启用后 F0.5 从 0.816 提到 0.833，检出率从 0.615 到 0.654，Earliness 从 0.539 到 0.625；M2 因为多个站室外温度传感器有问题，启用后 F0.5 掉到 0.625 甚至更低。所以最终没有做成全局开关，而是按厂商选配置，并且加了室外温度质量检查作为前置条件。需要说明的是，这个"按厂商选配置"是在同一批事件上选出来的，存在选择偏差，和论文按厂商给配置的做法一样。

短训练窗事件反而更容易检出。我们原本担心 M2 训练窗只有 20 到 30 天会导致欠拟合，但实际上训练窗少于 180 天的 23 个故障事件，基线检出率是 0.696，高于总体 0.440。这说明 M2 的短板不是数据量，而是别的东西（见第六节）。

## 六、传感器体检

因为上一条发现，我们做了一套逐站逐测点的体检：缺失率、常值或冻结（连续不变的小时数）、越界、分辨率、尖峰五类判定。规则上有两处需要按测点类型区分，否则误报会很多：设定值和状态量长期不变是正常的控制行为，不做常值判定；流量和功率在夏季停运期长期为 0 属于季节工况，记为 idle 而不是故障。

判定结果：93 个站、1599 个站-测点组合中，正常 1028 个，冻结 245 个，缺失 183 个，噪声 139 个，低分辨率 4 个。其中室外温度是重点，因为自适应阈值依赖它。

用 README 和本地探查记录里人工标注的坏传感器做验证：已知有问题的 6 个室外温度传感器（M1 的 19 号，M2 的 3、18、41、47、61 号），体检全部命中，没有漏报；另外新发现 7 个站存在长时间数值不变（M1 的 5、31 号，M2 的 7、17、21、28、45 号），最长连续不变 74 到 1474 小时，这些人工记录里没有。按"严重到需要降级"的口径统计，有 13 个站需要处理，涉及 10 个评估事件。

降级的做法是：坏传感器及其派生特征一起从特征矩阵里剔除（比如室外温度坏了，依赖它的供暖曲线残差、负荷指数、供暖季标记、缺失率也一起删），同时关闭自适应阈值。把降级接进协议后重跑 115 个事件，指标和"仅按质量门控关闭自适应阈值"完全一致（A 0.988、F0.5 0.737、检出率 0.560），没有回退。也就是说这个模块在当前 benchmark 上不体现为分数提升，它的作用是让坏站的特征矩阵不再吃错误信号，以及产出一份可以直接交给运维的传感器健康清单。

这里也把一个判断写清楚：主网温度在夏季连续 29 天不变的有 33 个站，那是停运工况而不是传感器故障。如果按"连续不变就是冻结"一刀切，会误删大量有效信号，这是做降级时最容易踩的坑。

## 七、跨站预训练没有成功

原本的计划是用其他站的正常数据预训练自编码器，再用目标站的数据微调，以此解决 M2 训练窗太短的问题。做了两版实现，都不成立。

防泄漏的处理是：给某个站预训练时，把这个站自己的数据从语料库里排除，等价于新站冷启动。语料库来自其余站，去掉首月调试期和维修扰动，每站抽样 6000 行。第一版把语料统一标准化后混合；第二版改成每个站先按自己的统计量标准化再混合，并把微调加强到 60 个 epoch、学习率 3e-4。

结果是第一版全事件 F0.5 0.753、检出率 0.500，第二版 F0.5 0.661、检出率 0.460，都低于不迁移的 0.769 和 0.560。短训练窗子集上同样没有收益：不迁移是 F0.5 0.879、检出率 0.696，第一版 0.824 / 0.652，第二版 0.783 / 0.565。

原因我们的判断是站间异质性太强：配置类型、测点集合、供暖曲线量级都不一样，预训练学到的是一个"平均站"，反而把目标站特有的正常模式抹平了；而单站自编码器在 30 维输入、两万行数据下其实已经拟合得不错，迁移带来的初始化收益抵不过分布不匹配的损失。

这个负结果对我们是有用的：它说明"每站自学习"在这套数据上不是妥协，而是更合适的做法。代码保留在 `src/pretrain.py` 和 `scripts/run_pretrain.py`，可以复现。

## 八、目前的局限

模型覆盖的是换热站站内设备与控制状态，不含管道本体。
存在域偏移。国内一次网温度更高（110 到 130 度）、供暖期更集中、部分站点没有生活热水储水箱、测点也更少。现在的设计是每站自校准（残差特征加本站阈值），国内落地需要按字段映射接本站一到两个月数据重新训练，不需要故障标签；但不能说成"用德国数据训练好直接拿国内用"。
监督模型的指标偏乐观。样本只有 50 个故障事件，正样本来自报修前的固定锚点；加入同站硬负样本后，窗口级 AUC 从 0.93 降到 0.78，后者才是可信的数字，报告里用的是这个口径。
故障类型细分不可用（准确率 0.142）。
没有独立测试集，超参和阈值都在同一批事件上交叉验证标定，和论文一样有过拟合风险。
M2 的指标明显弱于 M1，瓶颈是传感器质量与工况差异，不是数据量。

## 九、文件与复现

代码在 `src/`：数据加载与统一（`data.py`）、特征工程（`features.py`）、评估协议（`protocol.py`）、模型（`models.py`）、传感器体检（`quality.py`）、跨站预训练实验（`pretrain.py`）、模型产物接口（`inference.py`）。实验脚本在 `scripts/`，图表在 `reports/figures/`，各配置的指标 CSV 和 metrics.json 在 `reports/` 对应的实验目录下。

跑一遍主实验：

```
python scripts/run_baseline.py --variant default --out baseline_default
python scripts/run_baseline.py --variant cyclic --features phys2 --out final_phys2
python scripts/run_baseline.py --variant cyclic --features phys2 --adapt-thr --sensor-quality --out final_v4_sq
python scripts/run_supervised.py
python scripts/run_quality.py
python scripts/make_figures.py --runs reports/baseline_default:论文口径基线 reports/final_best:最终模型 --out-prefix final2
```

环境用 Python 3.13，依赖 numpy、pandas、scikit-learn、matplotlib，不需要 TensorFlow。本机沙箱禁止 Python 创建命名管道，所以监督模型脚本在导入 sklearn 前强制单线程，否则梯度提升的多线程后端会报 WinError 5；所有脚本都屏蔽了 sklearn 的收敛警告，它只表示"未完全收敛"，不影响结果。
