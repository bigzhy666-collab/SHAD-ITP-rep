# 数据说明

原始数据不入库。数据集压缩包 266 MB，解压后约 2.4 GB。

## 数据集

PreDist Dataset，由德国 Fraunhofer IEE 发布，地址 <https://zenodo.org/records/19496480>（DOI 10.5281/zenodo.19496480），版本 v2，许可 CC BY 4.0（可以再分发，但要署名）。包含 93 个换热站的运行时间序列，2012 年 3 月到 2020 年 7 月，约 1193 万行，中位采样间隔 10 分钟。

## 放置方法

从上面的地址下载 `predist_dataset.zip`，解压到任意目录，保证结构是这样：

```
<数据目录>/
├── manufacturer 1/
│   ├── operational_data/substation_1.csv ...
│   ├── faults.csv
│   ├── disturbances.csv
│   ├── normal_events.csv
│   ├── feature_descriptions.csv
│   └── configuration_types.csv
└── manufacturer 2/
    └── （同上）
```

然后二选一指定路径：设环境变量 `PREDIST_DATA`（PowerShell 下是 `$env:PREDIST_DATA="D:\data\predist"`），或者直接改 `src/common.py` 里 `DATA` 的默认值。验证一下：

```
python -c "from src.data import load_substation; print(load_substation('M1', 7).shape)"
```

## 会自动生成的文件

这些目录跑起来之后会自动出现，同样不进仓库：

- `数据缓存/` 是每个站清洗和重采样后的 pickle 缓存，约 240 MB，第一次调用 `load_substation` 时生成。
- `reports/*/results.pkl` 是每次实验的逐事件分数和持续性计数轨迹，重跑对应脚本就会重建。
- `reports/supervised/*.pkl` 是监督模型和窗口数据集，重跑 `run_supervised.py` 会重建。

## 已知的数据问题

实际是 93 个站，M1 35 个、M2 58 个，数据包里缺 M2 的 22、30、32 号站。

M2 部分站的室外温度传感器损坏或长期近常数（3、18、47、61 号），M1 的 19 号站有越界值。

M1 有多个站存在超过 30 天的大缺口，最长的一个是 4.6 年；M2 全部站点截止到 2020 年 4 月 2 日。

累计量表（电量、体积）存在计数器归零，约 35% 的相邻步长是非递增的，建模时已剔除，用功率和流量代替。

M2 的单位是 W、Wh、ml/h、ml，和 M1 的 kW、kWh、l/h、m³ 差 1000 倍，加载层已经统一。

更细的清点见[数据清点报告](../勘探/data_inventory.md)。
